# SRSP Per-Project Configuration

This file lives at the root of a project that uses the Silicon Ranch Spec Driven Development framework.
It is optional. When present, it overrides framework defaults for all specs in the project.
Per-spec `.srsp-config.md` inside `.claude/specs/<name>/` takes precedence over this file.

## Configuration keys

```yaml
test-command: npm test
commit-prefix: "feat"
branch-prefix: "feature"
pr-target: development
coverage-command: npm run coverage
stale-days: 14
ticket-base-url: "https://github.com/silicon-ranch-team/siliconranch-spec/issues/"
```

## Behavior

- `test-command`: command used by `/srsp-verify` and `/srsp-apply` to run tests.
- `commit-prefix`: prefix applied to generated commit messages (e.g., `feat`, `fix`, `chore`).
- `branch-prefix`: prefix suggested when creating a feature branch (e.g., `feature`, `feat`).
- `pr-target`: default target branch for PRs. Takes precedence over `base-branch` in `spec.md`.
- `coverage-command`: command used by `/srsp-coverage` to collect test coverage data.
- `stale-days`: number of days a spec can stay in the same stage before `/srsp-report` flags it as stale (default: 14).
- `ticket-base-url`: base URL used by `/srsp-link` to validate or build ticket links.

## Rules

- Unknown keys are ignored but warned about by `srsp doctor`.
- Empty values mean "use framework defaults".
- This file must use YAML frontmatter at the top.
